# Recap MCP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A remote MCP server on the user's home PC that lets Claude (mobile app) find shifts needing a recap, fill the Network Ninja Staff App recap from voice input and photos, and save it as a draft — never submitting it and never touching claims.

**Architecture:** One Python process: an `MCPServer` (mcp SDK v2) over Streamable HTTP at a secret path, plus a phone upload page on the same Starlette app. Pure recap logic (definition parsing, visibility, validation, payload building) lives in one module with no I/O; SQLite holds events, answers, photos; a small site client talks to the Staff App's JSON API with a bearer token obtained by a headless Playwright login.

**Tech Stack:** Python 3.13, `mcp>=2.3,<3` (brings starlette, uvicorn, httpx), `playwright`, `keyring`, `pillow`; `pytest` for tests. stdlib `sqlite3`, `difflib`.

**Spec:** `docs/superpowers/specs/2026-11-19-recap-mcp-design.md` — read it first; section numbers below (§) refer to it.

## Global Constraints

- Runtime deps are exactly: `mcp>=2.3,<3`, `playwright`, `keyring`, `pillow`. Dev: `pytest`. Nothing else.
- mcp v2 API: `from mcp.server.mcpserver import MCPServer, Image` (FastMCP no longer exists). `app = server.streamable_http_app(streamable_http_path=f"/{secret}/mcp", transport_security=TransportSecuritySettings(allowed_hosts=[...public host, "127.0.0.1:*", "localhost:*"]))` — without `allowed_hosts` the tunnel's Host header is rejected. Custom routes via `@server.custom_route(path, methods=[...])`.
- Site base: `https://staff.betprogram.networkninja.com/api/v1/`. Auth header `Authorization: Bearer <jwt>`.
- **Never** call `POST recap_response_set` (final submit) or any path containing `claim`. Drafts go only to `POST partial_recap_response_set`.
- Gallery deletes (`POST document/remove`) only for document ids recorded in the local `photos` table.
- Upload retry: retry only on connection error, HTTP 503, or JSON `error` in `IncompleteUpload|EmptyUpload|UploadStorageFailed`; max 3 attempts, delays 1s, 2s. Never retry a bare 500.
- Secrets (site username, password, JWT, connector secret) only in Windows Credential Manager via `keyring`, service name `recap-mcp`. Never logged, never in tool output, never in the repo.
- Connector secret: ≥32 chars from `secrets.token_urlsafe(32)`. Upload link token: `secrets.token_urlsafe(16)`, expires 60 min after creation.
- Site data refresh at most once per 5 minutes. Re-login when JWT `exp` is < 2 days away or any call returns 401 (once, then fail loudly).
- Images normalised to JPEG, long edge ≤ 2000 px, quality 85.
- `data/` (db, photos, def cache, log) is git-ignored. Test fixtures contain **no** staff names, emails or phones.

## Review Focus

1. **Dictated numbers/money arrive messy** ("$49.50", " 40 ", "40.0", "about forty") — clean ones coerce, unparseable ones are rejected with a message Claude can repeat, never stored as garbage. → Task 2 test `test_coerce_messy_voice_values`.
2. **An answer flips a condition** (trade spend yes → no) — spend, tip and receipt become hidden: they drop out of "missing" and out of the draft payload even though old answers are still stored. → Task 4 test `test_hidden_answers_not_sent`.
3. **Bar names said differently from the site** ("ernies inn" vs "ERNIE S INN", "tacos and craft" vs "Tacos & Craft") still match; two shifts at the same bar return both. → Task 3 test `test_match_normalises_names`.
4. **Save retried after a failure** (network drop after photos uploaded) — re-running `save_recap_draft` does not upload the same photo twice. → Task 7 test `test_save_draft_is_idempotent_for_photos`.
5. **Phone sends a non-image or HEIC the server can't read** — the upload page answers 400 with a readable message, nothing is stored, the server doesn't crash. → Task 8 test `test_upload_rejects_unreadable_image`.

### Task 2: Coercion, validation, what's missing

**Files:** Modify `recap_mcp/recap.py`; Test `tests/test_recap.py`

**Interfaces:**
- Consumes: `Field`, `parse_definition`, `visible_ids`, `find` (Task 1).
- Produces:
  ```python
  class AnswerError(ValueError): ...                       # message is user-readable
  def coerce(field: Field, raw: str | int | float | bool | list[str]) -> str
  def check_rules(fields: list[Field], answers: dict[str, str]) -> dict[str, str]  # instance_id -> error, visible fields only
  def missing(fields: list[Field], answers: dict[str, str]) -> dict[str, list[Field]]  # {"answers": [...], "uploads": [...]}
  ```

- Coercion per type: YES_NO accepts bool / yes/y/yeah/true/t/1 → `"t"`, no/n/false/f/0 → `"f"`; INTEGER strips spaces/commas, accepts `"40.0"`, rejects non-numeric and negatives; FLOAT2 strips `$`/commas → 2 decimals (`"49.5"` → `"49.50"`); MULTISELECT takes list or comma string of option **names** (case-insensitive) → `"|".join(ids)` in option order, unknown name → error listing valid names; TEXT/TEXTAREA strip, empty → error; FORMULA and IMAGE_UPLOAD → error ("set by the site" / "use the photo upload link"); any other type → error naming the type.
- `check_rules`: `lteValue` (≤ value), `ltField` (< referenced answer), `lteField` (≤ referenced answer); skipped when either side is empty or the field is hidden.
- `missing`: visible, required, unanswered, non-FORMULA fields; IMAGE_UPLOAD ones go to `"uploads"`, rest to `"answers"`. Image fields count as answered when `answers[instance_id]` is non-empty (Task 7 writes a placeholder `"photo"` when a local photo is attached to that field).
